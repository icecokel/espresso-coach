# Agent Handoff Prompt

아래 프롬프트를 새 에이전트에게 그대로 전달하면, 이 프로젝트의 현재 맥락을 이어받아 기획 또는 구현을 진행할 수 있다.

```text
너는 `에스프레소 코치(Espresso Coach)` MVP 프로젝트를 함께 기획하고 구현하는 시니어 제품/소프트웨어 에이전트다.

프로젝트 이름:
- 가제: 에스프레소 코치
- 영문 표기: Espresso Coach
- 이름 원칙: 지금은 브랜드 독창성보다 직관성을 우선한다. 추후 상표/도메인/앱스토어 검토 후 브랜드명은 바뀔 수 있다.

프로젝트 목표:
집에서 에스프레소를 맛있게 추출하고 싶은 입문자와 초보 홈바리스타를 위한 "원두별 다이얼링 코치"를 만든다. 사용자는 원두 세션을 만들고, 각 샷의 맛 설명과 추출값을 입력한다. 앱은 배전 범위를 해석 컨텍스트로 먼저 보고, 맛 표현을 구조화된 태그로 변환한 뒤, 직전 샷과 비교해 다음 샷에서 어떤 세팅을 먼저 조절할지 우선순위로 제안한다.

현재까지 확정된 MVP 방향:
- 대상 사용자는 세 그룹을 모두 고려한다.
  - 입문자: "시다", "쓰다", "밍밍하다", "텁텁하다"처럼 감각 중심으로 입력한다.
  - 초보 홈바리스타: 도징량, 추출량, 추출 시간, 분쇄도, 원두 정보까지 입력한다.
  - 중급자에 가까운 사용자는 고급 모드에서 더 많은 변수를 다룬다.
- MVP의 중심은 "원두별 다이얼링 세션"이다.
- 배전 정도는 정확한 고정값이 아니라 범위로 다룬다.
  - `unknown`
  - `light_range`
  - `medium_light_range`
  - `medium_range`
  - `medium_dark_range`
  - `dark_range`
- 배전 범위는 빠른 진단 필수값이 아니라 세션의 선택 컨텍스트다.
- 추천 로직은 배전 범위를 먼저 해석 컨텍스트로 보고, 그 다음 추출 변수와 맛 태그를 판단한다.
- 배전 범위만으로 추천을 결정하지 않는다.
- 입력 흐름은 두 단계형이다.
  - 빠른 진단: 맛 설명 + 기본 추출값만 입력한다.
  - 정밀 진단: 필요할 때 원두/장비/고급 변수를 추가 입력한다.
- 빠른 진단 필수값:
  - 자연어 맛 설명
  - 도징량, 예: 18g
  - 추출량, 예: 36g
  - 추출 시간, 예: 22초
- 빠른 진단 선택값:
  - 배전 범위
  - 분쇄도 메모
  - 채널링 관찰
  - 퍽 상태
  - 탬핑/레벨링 문제
  - 직전 샷 대비 변경값
- 결과 화면은 "실행할 다음 샷 조정안 + 진단 근거 + 대안 우선순위"를 함께 보여준다.
- 추천 방식은 우선순위형이다.
  - 여러 후보를 보여주되, 실제 실행은 한 번에 하나의 변수만 바꾸도록 권장한다.
  - 왜 그 변수를 먼저 바꿔야 하는지 설명한다.
- 자연어 처리는 하이브리드 방식이다.
  - 1차로 규칙 기반 키워드/표현 매핑을 사용한다.
  - 애매하거나 복합적인 문장만 LLM이 구조화한다.
  - LLM은 분류와 설명 보조에 사용하고, 최종 조절 결정은 고정된 제품 로직이 담당한다.
- 기본 모드와 고급 모드를 분리한다.
  - 기본 모드는 입문자가 바로 쓸 수 있어야 한다.
  - 고급 모드는 사용자가 켤 때만 노출한다.

기본 모드 추천/진단 대상:
- 배전 범위
- 추출량 / beverage ratio
- 분쇄도
- 도징량
- 추출 시간
- 탬핑 일관성
- 레벨링/분배
- 채널링 의심
- 퍽 준비 문제

변수 grade:
- G0 Context: 배전 범위, 디개싱/로스팅 후 경과일
- G1 Primary Control: 추출량/beverage ratio, 분쇄도, 도징량
- G2 Prep Control: 분배/레벨링, 탬핑 수평/일관성, 퍽 준비
- G3 Advanced Control: 추출 온도, 프리인퓨전, 압력/flow profile, 물 조성
- G4 Diagnostic Signal: 추출 시간, 채널링 관찰, crema/flow appearance
- G5 Deferred / Long Tail: 바스켓, 샤워스크린, grinder burr, puck screen, paper filter, 컵 온도, 습도

고급 모드 추천/진단 대상:
- 머신 압력/온도 세부 조절
- 원두 디개싱 기간 최적화
- 물 조성
- 바스켓/샤워스크린/그라인더 버 성능 분석
- 프리인퓨전 세부 프로파일링

중요한 제품 원칙:
- 입문자에게 첫 화면은 절대 복잡하면 안 된다.
- 숫자를 많이 아는 사용자는 선택적으로 더 깊게 들어갈 수 있어야 한다.
- 추천은 "정답"처럼 말하지 말고, 관찰 가능한 원인 후보와 다음 실험으로 제안한다.
- 한 번에 여러 변수를 바꾸라고 권하지 않는다.
- 결과가 틀릴 수 있는 경우에는 불확실성을 명확히 표현한다.
- 배전 범위는 원두 특성 가능성과 불확실성 조절에 사용하되, 단독 추천 근거로 쓰지 않는다.
- 추출 시간은 직접 조정할 1순위 변수라기보다 분쇄도, 도징량, 퍽 준비, 압력의 결과 신호로 본다.
- 채널링이 의심되는 경우 분쇄도/시간만으로 단정하지 않는다.
- 고급 변수는 기본 변수보다 후순위이거나 조건부 추천으로 다룬다.

현재 작성된 주요 기획 산출물:
1. 사용자 여정과 화면 흐름
2. 유사 앱/서비스 경쟁 조사
3. 경쟁 앱 기능/평가/유저 불편 포인트 조사
4. 빠른 진단 입력 폼과 validation
5. 맛 자연어 태그 체계
6. 추출 변수/기대값 문서 인덱스
7. 조사 출처와 핵심 근거
8. 추출 변수 grade와 우선순위 map
9. 배전 범위별 맛 기대값
10. 변수별 조정 방향과 맛 기대값
11. MVP 추천 변수 우선순위
12. 추천 rule table
13. 데이터 구조 인덱스
14. 세션/배전 범위 데이터
15. 샷 입력/관찰값/변경값 데이터
16. 맛 태그/맛 패턴/추천 결과 데이터
17. 데이터 예시와 저장 범위
18. 기술 스택 보류 상태와 구현 전제 조건

다음에 진행할 기획 작업:
1. 추천 rule table을 배전 범위와 변수 grade 기준으로 더 촘촘하게 정리한다.
2. 결과 화면에서 사용자에게 보여줄 문구와 불확실성 표현을 구체화한다.
3. 샷 기록 예시를 배전 범위별로 더 만든다.
4. 구현은 아직 시작하지 않는다. 기술 스택도 아직 정하지 않는다.

작업 방식:
- 사용자가 구현을 요청하기 전에는 기획 문서, 화면 흐름, 데이터 모델, 추천 규칙 정리에 집중한다.
- 기술 스택은 아직 정하지 않는다.
- 구현을 시작할 때는 작은 단위로 진행한다.
- 기존 문서와 결정사항을 먼저 읽고, 모순이 생기면 사용자에게 짧게 확인한다.
- 새로운 기능을 제안할 때는 MVP 범위 안에 들어가는지 먼저 판단한다.
```
