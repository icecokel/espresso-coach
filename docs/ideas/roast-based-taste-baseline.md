# Roast Based Taste Baseline

## Idea

배전 범위별로 기대 맛 기준을 두고, 사용자의 맛 표현을 그 기준 위에서 해석한다.

예:

| Roast Range | Expected Baseline | Diagnostic Sensitivity |
| --- | --- | --- |
| light range | 산미 높음, 단맛 늦게 열림, 바디 가벼움 | 날카로운 신맛과 짧은 추출에 민감 |
| medium range | 산미, 단맛, 바디 균형 | 비율과 분쇄도 변화 해석에 적합 |
| dark range | 쓴맛, 바디, 로스티함 증가 | 건조함, 재 같은 쓴맛, 과추출에 민감 |

## Why It Matters

같은 "시다"도 약배전에서는 원두 특성일 수 있고, 강배전에서는 추출 부족 신호일 수 있다. 배전 기준표는 앱이 맛 표현을 단순 키워드가 아니라 컨텍스트 기반 신호로 해석하게 만든다.

## Possible Flow

1. 세션에 배전 범위를 선택하거나 추정한다.
2. 맛 태그가 들어오면 배전 기대값과 비교한다.
3. 정상 특성일 가능성과 추출 문제 가능성을 나눠 계산한다.
4. 추천 결과에 "배전 특성일 수 있음" 또는 "추출 문제 가능성이 큼"을 표시한다.

## MVP Boundary

Allowed:
- 배전 범위별 기대값 표 사용
- 배전 범위가 `unknown`이면 중립 기준 사용
- 확신도 낮은 배전 정보는 보조 신호로만 사용

Not allowed:
- 배전 범위만으로 추천 결정
- 배전을 정확한 고정값처럼 저장
- 로스터 표기와 앱 해석을 동일하다고 단정

## Promotion Criteria

이 아이디어를 planning 문서로 승격하려면 아래가 필요하다.

- 배전 범위별 기대 맛 baseline
- 맛 태그별 배전 민감도
- `unknown` 배전의 fallback 규칙
- 원두 특성 가능성과 추출 문제 가능성의 문구 기준
